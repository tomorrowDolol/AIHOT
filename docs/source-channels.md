# 渠道：从“情报从哪来”选信源类型

[信源](sources.md) 讲的是六种 `kind` 怎么配。这份讲上一步：一个行业里真正的情报分散在十几类地方，**每一类先判断采集器读不读得到，再决定用哪种 `kind`**。判断错了，信源会在后台一直失败，或者抓回来一列导航链接。

以衡器/健康测量行业的一份竞品月报为例：产品、营销、资讯、渠道四块内容，几十个链接，出处只有十类地方，其中一半不是媒体。

## 先验证，再建源

一个渠道能不能自动抓，不看它“看起来像不像有列表”，看请求拿回来的是什么：

```bash
curl -sS -m 20 -A "Mozilla/5.0" https://example.com/news/list | head -c 400
```

- **能抓**：`<title>` 是栏目名，HTML 里能直接看到每条标题和日期，不执行 JS 也有内容 → `web_list` / `rss`。
- **半能抓**：有列表但日期在详情页，或列表是服务端渲染、翻页靠参数 → `web_list` + `detail` 补齐。
- **抓不到**：`<title>` 是“Sina Visitor System”“小米商城”这类通用标题，正文只有几百字节的跳转脚本，或直接 403/400 → 换通道，别硬配选择器。

抓不到时只有两条路：`external` 推送（自己的脚本或人工整理后推进来），或平台提供了接口/账号（`x_search`、`mp_account`）。**不要为了让渠道上线去加新的 `kind`**，除非它真的是这个行业唯一的入口。

## 十类渠道

| 渠道 | 典型内容 | `kind` | `tier` | 自动抓 |
|---|---|---|---|---|
| 竞品官网产品页与新闻 | 型号、规格、展会动态、公司公告 | `web_list` / `rss` | T1 | 多数可以，先验证 |
| 电商商品详情（价格一手） | 零售价、券后价、折扣、货描 | — | T1 | 基本不行，走 `external` |
| 电商店铺与行业站（B2B） | 出口报价、促销型号、起订量 | `web_list` | T1 | 不行，走 `external` |
| 众筹与众测平台 | 预售量、众筹金额、推广手法 | — | T1 | 不行（前端渲染），走 `external` |
| 官方社媒 | 发帖频率、话题、新品预告 | `x_search`（X）/ `external` | T1_5 | X 可以；微博、小红书、抖音不行 |
| 公众号 | 战略合作、联名、活动官宣 | `mp_account` | T1_5 | 可以，按请求计费 |
| 招聘页面 | 岗位结构变化，组织动向的先行信号 | `web_list` | T1_5 | 部分可以，多数没有日期 |
| 展会与协会 | 展期、政策、行业口径 | `web_list` | T1 | 官网多为前端渲染，走 `external` 或 RSS |
| 政策与合规（计量、认证） | 型式批准、新规、召回 | `rss` / `web_list` | T1 | 部分可以 |
| 行业媒体与搜索聚合 | 行业新闻、地方媒体、产业报道 | `rss` | T2 | 可以，搜索关键词比逐个媒体更省事 |

`tier` 按一手性定，不按重要性：竞品官网和它自己的店铺页是一手，社媒官方账号是 `T1_5`，媒体转述是 `T2`。

## 三条容易走错的路

**1. 电商页面抓不到，别指望 `web_list`。** 天猫、京东、阿里国际站的商品页对非浏览器请求返回跳转与验证脚本，页面里只有几百字节。价格这类一手数据要么用带登录态的脚本抓完推到 `POST /api/ingest/items`，要么人工整理月度快照推进来。

**2. 社交平台大多不是“网页”。** 微博对匿名请求只给 Sina Visitor System，Facebook 直接 400。X 有 `x_search`；国内平台只能靠第三方服务或自己的脚本 + `external`。

**3. 展会和众筹站是前端渲染。** 广交会、小米众筹这类站点返回的是空壳 HTML，标题一致、正文为空。这类内容适合让运营在活动节点人工推进来，不占采集预算。

## 价格轨迹不是信源，是信源之上的比对

“某型号 2022.9 到 2023.3 六个时点的报价，两次大促月均为区间最低”这种结论，任何订阅都给不出来：它需要**定期取快照、落库存、做差分**。

框架没有价格快照能力，也不要为此在信源层加开关。要就做成 `modules/` 里的模块，或让外部脚本把结构化的价格条目推到 `/api/ingest/items`，按 `market_data` / `price_change` 评价。信源层只负责“这个页面稳定可读”，比较是下一个环节的事。

## 内部数据：先想清楚给谁看

竞品的出口量、市占率、内部财务口径、招聘动向，对内部决策有用，但公开站是对外匿名读者的。这类信源：

- 用 `external` 接入，默认 `isolated`（不进任何公开页面），确认要公开再改 `editorial`；
- 只想当“热度证据”的（比如招聘、社媒发帖频率）用 `hot_signal`，不单独展示，只参与热度；
- 不要把内部数据源设成 `editorial` 就完事——它会连同数字一起出现在日报和 RSS 里。

## 一个可以照抄的 `web_list`

官网新闻栏目的信息量不大，但它是唯一能自动跟的一手渠道。验证过的配置长这样（永衡良品，`industry/sources.json` 的 `web-yeshm-news`）：

```json
{
  "url": "https://www.yeshm.com/news/list",
  "itemSelector": "div.news-item",
  "linkSelector": "a.yeshm-link",
  "publishedAtSelector": "p.date"
}
```

要点：

- `itemSelector` 选的是**每一条**新闻的外层容器，不是包住所有条目的那层；
- 日期写成“2023年11月14日”也能解析，不用配 `publishedAtRegex`；
- 列表页只翻第一页就够，历史存量靠首次导入的 `_aihot.initialBackfillLimit` 控制；
- 顺手记下这个源最近一次更新是什么时候。三年没更新的官网栏目照样能配，但它在“7 天没有新内容”里会被列出来——那是实际情况，不是配错了。

## 接入顺序

1. 先把**能自动抓且产出稳定**的建起来（官网、行业媒体、政策），它们决定日报有没有内容；
2. 再补需要外部脚本的渠道（电商价格、社媒、众筹），用同一个 `external` 口子推进来，先设 `isolated` 看一周；
3. 最后才是人工整理类（展会、榜单、内部报表），按节点推，不进日常采集节奏。
